# OTC Guarant Mini App — обновлённая версия

## Реализовано
- Telegram Mini App с серверной проверкой подписи `initData`.
- Создание сделок, уникальные ID, ссылка на покупателя, список сделок.
- Настраиваемая комиссия в админ-панели (0–30%; применяется к новым сделкам).
- USDT через Crypto Pay API (@CryptoBot): создание настоящего invoice через `createInvoice`.
- Подтверждение USDT только после `invoice_paid` webhook, проверки HMAC-подписи, invoice ID, payload, валюты и суммы. Повторный webhook не завершает обработку повторно.
- Рубли: ручная оплата СБП/картой. Покупатель отмечает «оплатил», администратор проверяет поступление вне приложения и только затем подтверждает.
- Статусы, споры, отмена в допустимых состояниях, журнал событий.
- Автоматическая миграция SQLite: добавляются поля invoice без удаления старых таблиц.

## Важно про деньги
Эта версия НЕ удерживает деньги на эскроу-счёте, НЕ отправляет автоматические выплаты продавцам и НЕ делает автоматические возвраты. Crypto Pay подтверждает получение USDT в платёжном приложении, но не обеспечивает блокировку Telegram NFT/подарка. До запуска реальных сделок определите юридическую схему, возвраты и разрешённость посреднических платежей в вашей юрисдикции. Не просите пользователей отправлять актив до выполнения правил сделки.

## Настройка Crypto Bot
1. В @CryptoBot откройте Crypto Pay → My Apps → Create App и получите API token. Для тестов используйте @CryptoTestnetBot и тестовый API.
2. В переменных окружения сервера задайте `CRYPTOPAY_TOKEN` (никогда не вставлять его в HTML/JS и не публиковать).
3. Сгенерируйте длинный случайный секрет для `CRYPTOPAY_WEBHOOK_PATH_SECRET`.
4. После деплоя укажите в Crypto Pay → My Apps → ваша app → Webhooks URL адрес:
   `https://ВАШ-ДОМЕН/webhooks/cryptopay/ВАШ_СЕКРЕТ`
   Путь должен точно совпадать с `CRYPTOPAY_WEBHOOK_PATH_SECRET`. Не публикуйте URL webhook.
5. Включите webhook и проверьте тестовой оплатой. Сервер обрабатывает только `invoice_paid` с валидной подписью.
6. Для production используйте HTTPS и постоянный диск/базу. Убедитесь, что webhook URL доступен снаружи.

Официальная документация: https://help.cr.bot/ru/articles/10279948-crypto-pay-api

## Переменные окружения
- `BOT_TOKEN` — токен Telegram-бота от BotFather.
- `APP_URL` — публичный HTTPS URL Mini App.
- `ADMIN_IDS` — Telegram ID администраторов через запятую.
- `COMMISSION_PERCENT` — стартовая комиссия; затем меняется в Mini App админом.
- `MIN_AMOUNT_RUB` — минимальная сумма сделки в рублях.
- `MIN_AMOUNT_USDT` — минимальная сумма сделки в USDT.
- `RUB_PAYMENT_DETAILS` — текст-инструкция для ручной оплаты. Не кладите сюда секретные данные; меняйте только на реквизиты, которые можно показывать покупателю.
- `CRYPTOPAY_TOKEN` — API-токен Crypto Pay.
- `CRYPTOPAY_BASE_URL` — mainnet `https://pay.crypt.bot/api`, testnet `https://testnet-pay.crypt.bot/api`.
- `CRYPTOPAY_WEBHOOK_PATH_SECRET` — длинный случайный секрет в URL webhook.
- `DB_PATH` — файл SQLite; путь должен сохраняться между перезапусками.

## Деплой Bot Host
Надёжнее создать два сервиса из одного репозитория/каталога:

**Web/API service**
- Build/install: `pip install -r requirements.txt`
- Start: `uvicorn api:app --host 0.0.0.0 --port $PORT`
- Домен: публичный HTTPS, который укажете в `APP_URL` и Crypto Pay Webhook URL.

**Bot worker**
- Start: `python bot.py`
- Те же `BOT_TOKEN`, `APP_URL`, `ADMIN_IDS`.
- Не запускайте несколько polling-воркеров с одним токеном.

Если хост предоставляет только один процесс, настройте отдельный worker или supervisor. `Procfile` — пример для платформ, которые его поддерживают.

## Проверка перед запуском
1. Откройте `/health` — должен вернуть `{"ok":true}`.
2. Запустите бота, откройте Mini App только через кнопку в Telegram.
3. Создайте тестовую RUB-сделку, отметьте оплату, убедитесь, что админ может подтвердить её, а обычный пользователь — нет.
4. На Crypto Pay testnet создайте USDT-сделку, подключите webhook, оплатите тестовый invoice и проверьте смену статуса на `awaiting_transfer`.
5. Проверьте неправильную подпись webhook (должен быть 401), повторный webhook (не должен повторно менять статус), и сумму меньше invoice.
6. Перед mainnet включите резервные копии базы и проверьте, кто имеет доступ к реквизитам и секретам.

## Ограничения текущего этапа
- Админ подтверждает рублёвое поступление только после самостоятельной проверки банка; скриншот не является доказательством зачисления.
- Крипто webhook проверяет invoice, который создал сервер. Не используйте публичные пользовательские callback-параметры как подтверждение оплаты.
- Комиссия фиксируется при создании сделки; изменение процента не пересчитывает уже созданные сделки.
- Нет авто-перевода продавцу, возвратов, таймаутов и полноценного KYC/anti-fraud. Не называйте это автоматическим эскроу.


## Режим воркера `/workzima`

Любой пользователь может написать `/workzima` в личном чате с ботом. Бот разблокирует вкладку «Режим воркера» только для Telegram-аккаунта, который отправил команду. Это **не** выдаёт права администратора. Баланс, комиссия и подтверждение платежей по-прежнему доступны только ID из `ADMIN_IDS` (по умолчанию владелец `2120598576`).

В `.env` обязательно задайте одинаковый длинный случайный `INTERNAL_API_SECRET` для API и бота. `API_BASE_URL` должен указывать на адрес API. Если API и бот используют разные хранилища, для корректной работы worker unlock используйте одну общую постоянную БД/том; рекомендуемый вариант — общая SQLite на persistent volume либо PostgreSQL при раздельных контейнерах.
